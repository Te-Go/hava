📡 API ARCHITECTURE — THREE-TIER DATA STRATEGY

The Critical Finding: MGM + Open-Meteo Dual Source

For Turkish-focused apps, MGM (Türkiye Devlet Meteoroloji İşleri Genel Müdürlüğü) is the data source that carries domestic authority. It exposes city-level and regional forecasts from the Turkish State Meteorological Service. However, the MGM feed is an unofficial XML scrape — not a documented public API. It can change structure without notice. Pair it with Open-Meteo as the backbone and MGM for trust-signal display.

TIER 1: Primary Forecast — Open-Meteo (FREE, no API key)

Open-Meteo integrates weather models from over 15 national weather services including ECMWF, DWD, NOAA, Météo-France, JMA, KMA and more. The best_match option automatically selects the highest-resolution model for any location. Response times are below 10ms.

// src/lib/openmeteo.ts — Primary weather data source



const BASE_URL = 'https://api.open-meteo.com/v1/forecast';



export async function fetchWeatherForecast(lat: number, lon: number): Promise<WeatherData> {

  const params = new URLSearchParams({

    latitude:  lat.toString(),

    longitude: lon.toString(),

    timezone:  'Europe/Istanbul',

    // Current conditions

    current: [

      'temperature_2m',

      'relative_humidity_2m',

      'apparent_temperature',

      'precipitation',

      'rain',

      'weather_code',

      'wind_speed_10m',

      'wind_direction_10m',

      'uv_index',

      'is_day',

    ].join(','),

    // Hourly (48 hours)

    hourly: [

      'temperature_2m',

      'precipitation_probability',

      'precipitation',

      'weather_code',

      'wind_speed_10m',

      'uv_index',

      'visibility',

      'relative_humidity_2m',

    ].join(','),

    // Daily (16 days)

    daily: [

      'weather_code',

      'temperature_2m_max',

      'temperature_2m_min',

      'sunrise',

      'sunset',

      'uv_index_max',

      'precipitation_sum',

      'precipitation_probability_max',

      'wind_speed_10m_max',

      'wind_direction_10m_dominant',

    ].join(','),

    // Extended parameters

    forecast_days: '16',

    wind_speed_unit: 'kmh',

    models: 'best_match',

  });



  const res = await fetch(`${BASE_URL}?${params}`, {

    next: { revalidate: 1800 }, // Cache 30 minutes — ISR freshness

    signal: AbortSignal.timeout(5000),

  });



  if (!res.ok) throw new Error(`Open-Meteo error: ${res.status}`);

  return res.json();

}

const AFAD_QUAKE_URL = 'https://deprem.afad.gov.tr/apiv2/event/filter';



export async function fetchRecentEarthquakes() {

  const endDate   = new Date().toISOString();

  const startDate = new Date(Date.now() - 24 * 60 * 60 * 1000).toISOString();



  const res = await fetch(

    `${AFAD_QUAKE_URL}?start=${startDate}&end=${endDate}&minmag=2.0&orderby=timedesc&limit=50`,

    }

  );



  if (!res.ok) {

    return fetchKandilliEarthquakes();

  }

  return res.json();

}

Requirements

Turkish Character Handling (Critical)

Standard .toLowerCase() breaks Turkish. 'I' must become 'ı' (not 'i'), and 'İ' must become 'i'. This is a known runtime failure in Turkish web apps.

// src/lib/turkishSearch.ts — The correct Turkish-aware search engine



// Turkish locale-aware normalisation

export function normalizeTurkish(str: string): string {

  return str

    .toLocaleLowerCase('tr-TR')           // İ→i, I→ı correctly

    .replace(/ğ/g, 'g')

    .replace(/ü/g, 'u')

    .replace(/ş/g, 's')

    .replace(/ı/g, 'i')

    .replace(/ö/g, 'o')

    .replace(/ç/g, 'c')

    .trim();

}



// Turkish character-tolerant fuzzy match

// Allows user to type "istanbul" or "İstanbul" or "istanbul" — all match

export function turkishFuzzyMatch(query: string, target: string): boolean {

  return normalizeTurkish(target).includes(normalizeTurkish(query));

}

// src/components/search/LocationSearch.tsx

'use client';



import { useState, useRef, useEffect, useCallback } from 'react';

import { useRouter } from 'next/navigation';

import { LOCATIONS, type TurkishLocation } from '@/data/turkish-locations';

import { turkishFuzzyMatch, normalizeTurkish } from '@/lib/turkishSearch';



type SearchState = 'idle' | 'searching' | 'results' | 'no-results' | 'error';



export function LocationSearch({ compact = false }: { compact?: boolean }) {

  const [query,    setQuery]    = useState('');

  const [results,  setResults]  = useState<TurkishLocation[]>([]);

  const [state,    setState]    = useState<SearchState>('idle');

  const [focused,  setFocused]  = useState(false);

  const [selected, setSelected] = useState(-1); // Keyboard nav index

  const inputRef  = useRef<HTMLInputElement>(null);

  const listRef   = useRef<HTMLUListElement>(null);

  const router    = useRouter();



  // Debounced search

  const search = useCallback((q: string) => {

    if (q.trim().length < 2) {

      setResults([]);

      setState('idle');

      return;

    }



    setState('searching');



    // Client-side fuzzy search with Turkish normalisation

    const matches = LOCATIONS

      .filter(loc =>

        turkishFuzzyMatch(q, loc.name) ||

        turkishFuzzyMatch(q, loc.province) ||

        turkishFuzzyMatch(q, `${loc.name} ${loc.province}`)

      )

      .sort((a, b) => {

        // Exact province match ranks higher

        const aExact = normalizeTurkish(a.name).startsWith(normalizeTurkish(q));

        const bExact = normalizeTurkish(b.name).startsWith(normalizeTurkish(q));

        if (aExact && !bExact) return -1;

        if (!aExact && bExact)  return 1;

        // Sort by population (larger cities first)

        return (b.population ?? 0) - (a.population ?? 0);

      })

      .slice(0, 8); // Max 8 results in dropdown



    setResults(matches);

    setState(matches.length > 0 ? 'results' : 'no-results');

    setSelected(-1);

  }, []);



  // Debounce effect

  useEffect(() => {

    const timer = setTimeout(() => search(query), 200);

    return () => clearTimeout(timer);

  }, [query, search]);



  // Keyboard navigation

  const handleKeyDown = (e: React.KeyboardEvent) => {

    if (!results.length) return;



    if (e.key === 'ArrowDown') {

      e.preventDefault();

      setSelected(prev => Math.min(prev + 1, results.length - 1));

    } else if (e.key === 'ArrowUp') {

      e.preventDefault();

      setSelected(prev => Math.max(prev - 1, -1));

    } else if (e.key === 'Enter') {

      e.preventDefault();

      const target = selected >= 0 ? results[selected] : results[0];

      if (target) navigateTo(target);

    } else if (e.key === 'Escape') {

      setFocused(false);

      inputRef.current?.blur();

    }

  };



  const navigateTo = (location: TurkishLocation) => {

    setQuery('');

    setFocused(false);

    router.push(`/${location.slug}/`);

  };



  const locationTypeLabel = (type: TurkishLocation['type']) => {

    return type === 'il' ? 'İl' : type === 'ilce' ? 'İlçe' : 'Mahalle';

  };



  return (

    <div className="search-wrapper" role="search" aria-label="Konum ara">

      <div className={`search-input-row ${focused ? 'focused' : ''}`}>

        {/* Search icon */}

        <svg className="search-icon" width="18" height="18" viewBox="0 0 24 24"

          fill="none" stroke="currentColor" strokeWidth="2" aria-hidden="true">

          <circle cx="11" cy="11" r="8"/><path d="m21 21-4.35-4.35"/>

        </svg>



        <input

          ref={inputRef}

          type="search"

          // CRITICAL: inputMode and lang for Turkish keyboard on mobile

          inputMode="search"

          lang="tr"

          autoComplete="off"

          autoCorrect="off"

          autoCapitalize="off"

          spellCheck="false"

          value={query}

          onChange={e => setQuery(e.target.value)}

          onFocus={() => setFocused(true)}

          onBlur={() => setTimeout(() => setFocused(false), 200)}

          onKeyDown={handleKeyDown}

          placeholder="Şehir veya ilçe adı girin..."

          aria-label="Konum ara"

          aria-autocomplete="list"

          aria-expanded={state === 'results'}

          aria-controls="search-results"

          aria-activedescendant={selected >= 0 ? `result-${selected}` : undefined}

          className="search-input"

        />



        {/* Clear button */}

        {query.length > 0 && (

          <button

            onClick={() => { setQuery(''); inputRef.current?.focus(); }}

            className="search-clear"

            aria-label="Aramayı temizle"

          >

            ✕

          </button>

        )}



        {/* GPS button */}

        <button

          onClick={handleGPSLocation}

          className="search-gps"

          aria-label="Konumumu kullan"

          title="Konumumu kullan"

        >

          📍

        </button>

      </div>



      {/* Results dropdown */}

      {focused && state !== 'idle' && (

        <div className="search-dropdown glass-card" role="listbox">

          {state === 'searching' && (

            <div className="search-status">

              <span className="search-spinner" aria-live="polite">Aranıyor...</span>

            </div>

          )}



          {state === 'results' && (

            <ul

              ref={listRef}

              id="search-results"

              role="listbox"

              aria-label="Konum sonuçları"

            >

              {results.map((loc, i) => (

                <li

                  key={loc.id}

                  id={`result-${i}`}

                  role="option"

                  aria-selected={i === selected}

                  className={`search-result-item ${i === selected ? 'active' : ''}`}

                  onClick={() => navigateTo(loc)}

                  onMouseEnter={() => setSelected(i)}

                >

                  <div className="result-icon">

                    {loc.type === 'il' ? '🏙️' : '📍'}

                  </div>

                  <div className="result-text">

                    <span className="result-name">{loc.name}</span>

                    {loc.type !== 'il' && (

                      <span className="result-province">{loc.province}</span>

                    )}

                  </div>

                  <div className="result-meta">

                    <span className="result-type-badge">

                      {locationTypeLabel(loc.type)}

                    </span>

                  </div>

                </li>

              ))}

            </ul>

          )}



          {state === 'no-results' && query.trim().length >= 2 && (

            <div className="search-no-results" role="status" aria-live="polite">

              <p className="no-results-icon">🔍</p>

              <p className="no-results-title">

                "<strong>{query}</strong>" bulunamadı

              </p>

              <p className="no-results-hint">

                Şehir veya ilçe adını Türkçe karakterlerle yazın.

                <br />

                Örnek: "İstanbul", "Çanakkale", "Şanlıurfa"

              </p>

            </div>

          )}

        </div>

      )}

    </div>

  );

}



// GPS auto-detection helper

async function handleGPSLocation() {

  if (!navigator.geolocation) {

    alert('Tarayıcınız konum özelliğini desteklemiyor.');

    return;

  }



  navigator.geolocation.getCurrentPosition(

    async (pos) => {

      const { latitude: lat, longitude: lon } = pos.coords;



      // Reverse geocode using Open-Meteo Geocoding API

      const res = await fetch(

        `https://geocoding-api.open-meteo.com/v1/reverse?latitude=${lat}&longitude=${lon}&language=tr&count=1`

      );

      const data = await res.json();



      if (data.results?.[0]) {

        const loc = data.results[0];

        // Navigate to closest matching location in our database

        window.location.href = `/konum?lat=${lat}&lon=${lon}&name=${encodeURIComponent(loc.name)}`;

      }

    },

    (error) => {

      const messages: Record<number, string> = {

        1: 'Konum izni reddedildi. Tarayıcı ayarlarından konum iznini etkinleştirin.',

        2: 'Konumunuz alınamadı. Lütfen tekrar deneyin.',

        3: 'Konum alımı zaman aşımına uğradı.',

      };

      alert(messages[error.code] ?? 'Konum alınamadı.');

    },

    { timeout: 8000, maximumAge: 300000 } // 5-minute cache for GPS result

  );

}

Caching strategy for traffic:

TomTom traffic tiles are cached by Cloudflare CDN at edge.

// For district-level search, query Open-Meteo's free geocoding API

// This returns Turkish ilçe and even mahalle names

// Response is cached in Redis for 24 hours (location data doesn't change)



export async function searchLocations(query: string): Promise<TurkishLocation[]> {

  // First: check our static province list (instant, no API)

  const staticMatches = TURKEY_PROVINCES.filter(p => turkishFuzzyMatch(query, p.name));

  if (staticMatches.length > 0) return staticMatches;



  // Second: query Open-Meteo Geocoding (free, no API key)

  const cacheKey = `geo:${normalizeTurkish(query)}`;

  const cached = await redis.get(cacheKey);

  if (cached) return JSON.parse(cached);



  const res = await fetch(

    `https://geocoding-api.open-meteo.com/v1/search?name=${encodeURIComponent(query)}&count=8&language=tr&countryCode=TR`,

    { signal: AbortSignal.timeout(2000) }

  );

  const data = await res.json();



  const results: TurkishLocation[] = (data.results ?? []).map((r: any) => ({

    id:       `${r.id}`,

    name:     r.name,

    province: r.admin1 ?? '',    // Province/il name

    district: r.admin2 ?? '',    // District/ilçe name

    type:     r.feature_code === 'PPLA' ? 'il' : 'ilce',

    lat:      r.latitude,

    lon:      r.longitude,

    slug:     buildSlug(r),

    population: r.population ?? 0,

  }));



  // Cache for 24 hours — location names don't change

  await redis.setex(cacheKey, 86400, JSON.stringify(results));

  return results;

}



Why this is the right approach:

81 provinces hard-coded: zero latency, zero cost, handles 95% of searches

Open-Meteo Geocoding for districts: free, no rate limits, returns Turkish names

Redis caches every unique search query for 24h → only first search of each query hits the API

1,000 unique district searches per day × 1 API call each = 1,000 calls/day (well within free tier)

function addWeatherLayer(map: MapLibreMap, variable: RadarLayer) {

  const omUrl = `https://map-tiles.open-meteo.com/data_spatial/dwd_icon/latest.json?variable=${variable}&time_step=current_time_1H`;



  map.addSource('weather-source', {

    type: 'raster',

    url:  `om://${omUrl}`,   // Open-Meteo protocol handler

    tileSize: 256,

    maxzoom:  10,

  });



  map.addLayer({

    id:     'weather-layer',

    type:   'raster',

    source: 'weather-source',

    paint:  { 'raster-opacity': 0.70 },

  });

}



function addLocationPin(map: MapLibreMap, lat: number, lon: number, name: string) {

    .addTo(map);

}

The Problem with Weather Apps at Scale

A typical weather app wants to have pages for all 81 provinces × their districts × multiple forecast types = potentially 5,000–50,000 pages. Google's March 2024 update introduced "scaled content abuse" as a new spam category. Sites that churn out many similar pages targeting slight keyword variations are seeing demotions. Location pages that use the same template in dozens of cities have lost visibility.

HavaPro's Doorway Defense Strategy

Principle 1: Each page must be a genuine destination. Every city page shows real, live, uniquely-fetched weather data for that exact city. If Istanbul has rain and Ankara has sun, those two pages look and feel completely different because the data IS different.

Principle 2: Minimum content differentiation per city. Each city/district page gets a static editorial section (150-300 words) that is hand-written or AI-written-and-human-reviewed per city. Content includes:

Local climate characterisation ("İstanbul'un Boğaz iklimi...")

Historical weather records for that city

Principle 3: Engagement signals that prove value. Every city page has: hourly chart, 16-day forecast, life recommendations, air quality widget, local news, marine conditions (if coastal). Average session on a city page target: >3 minutes. Low bounce rate proves to Google the page is a genuine destination.

Principle 4: District pages require MORE content, not less. District-level pages (istanbul/kadikoy, ankara/cankaya) are higher-precision with more local detail. These are the pages no competitor has. They get:

GPS-matched weather for the exact district coordinates

Neighbourhood-specific commentary

Internal links to all surrounding districts



❓ PRINCIPLE 5 CLARIFIED: Index Budget 

This is an important distinction.

What "index budget management" means: It refers exclusively to which pages Google actively indexes and ranks — not to which locations users can access data for. These are two completely different things.

Every location in Turkey should be accessible to users from day one. If a user types "Erzincan" into the search bar, they get Erzincan's weather immediately. The data comes live from Open-Meteo based on coordinates, so there is no database to pre-populate. Every location on Earth is available because Open-Meteo serves any latitude/longitude.

What NOT to do on the SEO side: The index budget principle refers to NOT submitting 400+ city/district pages to Google's sitemap on launch day. Here is why:

Google allocates a "crawl budget" to each domain — a limited number of pages it will crawl and index per day. A new domain with zero authority that suddenly has 400 pages submitted to its sitemap signals thin programmatic content to Google's algorithms, even if the pages are genuinely different. This is exactly the pattern that triggers doorway page detection.

The correct strategy is:

WHAT USERS CAN ACCESS (Day 1): ALL locations via GPS + search bar

                                Any coordinates → Open-Meteo returns data instantly

                                No pre-built page needed for user data access



WHAT GOOGLE INDEXES (phased):

Day 1 sitemap:    15 city pages (your 15 domain-backed cities)

Month 3 sitemap:  35 city pages (next 20 highest-volume cities)

Month 6 sitemap:  81 city pages (all provinces)

Month 9 sitemap:  81 + 75 district pages (top 5 districts × 15 major cities)

Moon Phase — Best Solution: Calculate Client-Side (Zero API Cost)

Moon phase is a deterministic mathematical calculation based on date alone. No API needed for basic moon phase — it can be computed entirely in the browser with a simple algorithm accurate to within minutes for the next 100 years. Reserve APIs for moonrise/moonset times.

export interface MoonPhaseData {

  phase:         number;          // 0 = new moon, 0.5 = full moon, 1 = new moon again

  phaseName:     string;          // Turkish phase name

  phaseNameEN:   string;          // English for icon mapping

  illumination:  number;          // 0–100% lit

  emoji:         string;          // 🌑🌒🌓🌔🌕🌖🌗🌘

  icon:          string;          // Meteocons icon name

  daysToFull:    number;          // Days until next full moon

  daysToNew:     number;          // Days until next new moon

  isWaxing:      boolean;

  isSupermoon:   boolean;         // Moon within 90% of perigee distance

}



// Jean Meeus algorithm — precise, no dependencies

export function getMoonPhase(date: Date = new Date()): MoonPhaseData {

  const jd = dateToJulian(date);



  // Days since known new moon (January 6, 2000 18:14 UTC = JD 2451549.75)

  const daysSinceNewMoon = jd - 2451549.75;

  const moonCycle = 29.53058867; // Synodic period in days

  const phase = ((daysSinceNewMoon % moonCycle) + moonCycle) % moonCycle;

  const phaseRatio = phase / moonCycle; // 0–1



  // Illumination (approximate)

  const illumination = Math.round((1 - Math.cos(phaseRatio * 2 * Math.PI)) / 2 * 100);



  // Phase name and emoji

  const { name, nameEN, emoji, icon } = getPhaseDetails(phaseRatio);



  return {

    phase:        phaseRatio,

    phaseName:    name,

    phaseNameEN:  nameEN,

    illumination,

    emoji,

    icon,

    daysToFull:   Math.round(((0.5 - phaseRatio + 1) % 1) * moonCycle),

    daysToNew:    Math.round(((1 - phaseRatio) % 1) * moonCycle),

    isWaxing:     phaseRatio < 0.5,

    isSupermoon:  false, // Simplified — add perigee calculation if needed

  };

}

function dateToJulian(date: Date): number {

  const a = Math.floor((14 - date.getUTCMonth() - 1) / 12);

  const y = date.getUTCFullYear() + 4800 - a;

  const m = date.getUTCMonth() + 1 + 12 * a - 3;

  return date.getUTCDate()

    + Math.floor((153 * m + 2) / 5)

    + 365 * y

    + Math.floor(y / 4)

    - Math.floor(y / 100)

    + Math.floor(y / 400)

    - 32045

    + (date.getUTCHours() - 12) / 24

    + date.getUTCMinutes() / 1440

    + date.getUTCSeconds() / 86400;

}

Dew Point — Calculated from Open-Meteo Data (No Extra API Call)

Open-Meteo does not return dew point directly but provides temperature and relative humidity. Dew point is a standard meteorological formula:

// src/lib/formatters.ts — Add to existing file



/**

 * Magnus formula — standard WMO approximation

 * Accurate to ±0.35°C for temperatures between −40°C and +60°C

 */

export function calcDewPoint(tempC: number, relHumidity: number): number {

  const a = 17.625;

  const b = 243.04; // °C



  const alpha = (a * tempC) / (b + tempC) + Math.log(relHumidity / 100);

  const dewPoint = (b * alpha) / (a - alpha);



  return Math.round(dewPoint * 10) / 10; // Round to 1 decimal

}



// Human-readable comfort level from dew point (used in Turkish UI)

export function dewPointComfort(dewPointC: number): string {

  if (dewPointC < 10)  return 'Kuru ve rahat';

  if (dewPointC < 21)  return 'Nemli, hafif bunaltıcı';

  if (dewPointC < 24)  return 'Çok nemli, bunaltıcı';

  return                      'Aşırı nemli, bunaltıcı';

}

interface AutoThemeOptions {

  sunrise: string;  // ISO string e.g. "2026-07-14T05:43:00+03:00"

  sunset:  string;

  manual?: 'dark' | 'light';  // User override — respected indefinitely

}



export function getAutoTheme({ sunrise, sunset, manual }: AutoThemeOptions): 'dark' | 'light' {

  // User's explicit choice always wins

  if (manual) return manual;



  const now      = new Date();

  const riseTime = new Date(sunrise);

  const setTime  = new Date(sunset);



  // 30-minute transition buffer around sunrise/sunset

  const buffer   = 30 * 60 * 1000;



  const isDaytime = now >= new Date(riseTime.getTime() - buffer)

                 && now <= new Date(setTime.getTime()  + buffer);



  return isDaytime ? 'light' : 'dark';

}

function havapro_get_cached_weather_data($data) {

    $city_slug = sanitize_text_field($data['slug']);

    $geo_matrix = [

        'istanbul' => ['lat' => 41.0082, 'lon' => 28.9784],

        'ankara'   => ['lat' => 39.9334, 'lon' => 32.8597],

        'antalya'  => ['lat' => 36.8969, 'lon' => 30.7133]

    ];



    if (!array_key_exists($city_slug, $geo_matrix)) {

        return new WP_Error('unknown_location', 'Location coordinate mapping missing', array('status' => 404));

    }



    $lat = $geo_matrix[$city_slug]['lat'];

    $lon = $geo_matrix[$city_slug]['lon'];



    // Construct highly performant open-meteo query call asynchronously

    $target_url = "https://api.open-meteo.com/v1/forecast?latitude={$lat}&longitude={$lon}&timezone=Europe%2FIstanbul&current=temperature_2m,relative_humidity_2m,apparent_temperature,precipitation,weather_code,wind_speed_10m,uv_index&hourly=temperature_2m,precipitation_probability,weather_code&daily=weather_code,temperature_2m_max,temperature_2m_min&forecast_days=16";

    if (is_wp_error($response)) {

import { NextRequest, NextResponse } from 'next/server';



export async function GET(request: NextRequest) {

  const { searchParams } = new URL(request.url);

  const lat = searchParams.get('lat');

  const lon = searchParams.get('lon');



  if (!lat || !lon) {

    return NextResponse.json({ error: 'Missing geo parameters' }, { status: 400 });

  }



  try {

    const upstreamUrl = `https://api.open-meteo.com/v1/forecast?latitude=${lat}&longitude=${lon}&current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m&timezone=Europe%2FIstanbul`;

    

    const response = await fetch(upstreamUrl, {

      next: { revalidate: 300 }, // Strict internal 5-minute cache target

    });



    if (!response.ok) throw new Error("Upstream rejected package parameters.");

    const payload = await response.json();



    return NextResponse.json(payload, {

      status: 200,

      headers: {

        'Cache-Control': 'public, s-maxage=300, stale-while-revalidate=60',

      },

    });

  } catch (err) {

    return NextResponse.json({ error: 'Meteorological provider fault' }, { status: 502 });

  }

}

We must build HavaPro on Next.js 15. The 3 Core Reasons Why

1. The Dynamic "Time-to-First-Byte" & First-Crawl Indexing Win

Weather intent is highly temporal. When a storm or sudden temperature drop hits Istanbul, search volume surges dramatically. Under a client-side React model, search crawlers see a blank template page because the dynamic weather data hasn't loaded from the client yet. Next.js 15 serves fully-rendered meteorological text and dynamic title tags (e.g., "İstanbul Hava Durumu: 22°C ☀️") directly on the initial HTTP response. Google indexes our freshly updated page immediately on its first crawl pass.

2. Incremental Static Regeneration (ISR) as our Server Shield

If we run a pure React SPA, 1,000,000 concurrent mobile users on a rainy Tuesday will trigger 1,000,000 separate client-side API requests directly to our database or third-party weather API. We set a revalidation interval of 15 minutes. When 1,000,000 users visit /istanbul/, they receive a lightning-fast static page from our Hostinger/Cloudflare cache. Only one server call is made every 15 minutes to refresh the file. This keeps our Hostinger CPU usage at nearly 0% even during viral spikes.

3. Zero Cumulative Layout Shift (CLS)

Google heavily penalizes sites where layout elements shift as assets load (such as ads loading in late, dynamic weather charts expanding, or text sizes resizing after dynamic state updates). Next.js 15 handles font and layout optimization out of the box. By pre-sizing our Bento Grid widgets on the server side, we guarantee a CLS score of 0.00, satisfying Google's strict UX requirements.
